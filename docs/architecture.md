# Архитектура ALLIN

Актуально на 4 ноября 2026 года, после унификации каталогов. Прикладной код разделён на `app`, `features` и `shared`. Alias `@/*` указывает на корень репозитория; `src/` не используется.

## Каталоги

```text
app/                           Маршруты, redirect и layout Expo Router
features/                      Код предметных областей
  auth/                        Вход, регистрация, выбор роли, авторизация
  home/                        Главная, магазины и товары
  search/                      Поиск на главной
  services/                    Каталог и категории услуг
  orders/                      Заказы и детали заказа
  profile/                     Профиль, адреса, настройки и отзывы
  transport/                   Неактивный каркас без экранов и маршрутов
  system/                      Обновление приложения и общий modal-route
shared/                        Код, используемый несколькими фичами
  api/                         Axios, QueryClient, клиент и адаптеры Supabase
  components/                  Общие компоненты: имя-компонента/index.tsx
  constants/                   Конфигурация, endpoints, query keys, ресурсы
  hooks/                       Общие hooks
  lib/                         Хранение токенов, media, toast, фабрика store
  mocks/                       Демонстрационные данные
  store/                       Общие stores темы, модалок и уведомлений
  theme/                       Токены, светлая/тёмная тема, существующие палитры
  types/                       Общие типы и контракты
  utils/                       Чистые вспомогательные функции
assets/                        Изображения и шрифты
docs/                          Документация
.agents/skills/                Проектные навыки
```

Конфигурация, `README.md`, `AGENTS.md` и существующий серверный скрипт остаются в корне. Служебные `.expo`, `.vscode` и зависимости не относятся к структуре прикладного кода.

## Единый формат фичи

У всех восьми фич один набор каталогов:

```text
features/<domain>/
  api/                         Запросы и мутации этой области
  components/                  Компоненты, специфичные для фичи
  hooks/                       Повторно используемая логика фичи
  screens/                     Экраны пользовательских сценариев
  store/                       Клиентское состояние фичи
  types/                       Доменные типы
  utils/                       Чистые функции фичи
  index.ts                     Публичные контракты для других фич
```

Пустые каталоги закреплены `.gitkeep`; это каркас для дальнейшей реализации. Синонимы `helpers`, `stores`, технические `services` и дублирующие пути удалены. Название `features/services` сохранено, потому что обозначает услуги как предметную область.

## Именование и импорты

- Файлы и каталоги используют `kebab-case`: `login-screen.tsx`, `use-auth-store.ts`, `query-client.ts`.
- Компоненты и типы в коде сохраняют `PascalCase`: `LoginScreen`, `ThemeTokens`.
- Общий компонент всегда находится в собственной папке: `shared/components/button/index.tsx`. Варианты платформ находятся рядом: `icon-symbol/index.tsx` и `icon-symbol/index.ios.tsx`.
- Импорт компонента идёт прямо из его папки: `import { Button } from "@/shared/components/button"`. Общих barrel-файлов `ui`, `atoms` и `molecules` больше нет.
- Одноимённые реализации с разными контрактами получили явные пути: `button` и `themed-button`, `input` и `themed-input`, `badge` и `themed-badge`. Их API и внешний вид при структурном переносе сохранены.
- Для маршрутов действуют специальные имена Expo Router: `_layout.tsx`, `(auth)`, `(tabs)`. Их не следует переименовывать по общему правилу.

## Маршруты и экраны

Главная вкладка содержит закреплённый поиск и полный каталог категорий с подкатегориями. Рекомендаций и горизонтальных быстрых категорий на ней нет. Заголовок категории открывает нижнюю панель `CategorySheet` с её подкатегориями; выбранная категория — локальное состояние `CatalogCategories`. Навигация: главная → панель подкатегорий → выдача → предложение; плитка на главной сразу открывает выдачу. Кнопка под сеткой панели открывает весь раздел; оба перехода выполняются после закрытия панели через явные callbacks. Старый `/categories` перенаправляет на главную. Четыре вкладки: «Услуги», «Избранное», «Заказы», «Профиль». Транспорт и карта отсутствуют в навигации. Подробная карта и ограничения описаны в [catalog-routing.md](catalog-routing.md).

Экраны размещены в `features/*/screens`; маршрут реэкспортирует default-компонент:

```tsx
export { default } from "@/features/auth/screens/login-screen";
```

`app/_layout.tsx` собирает провайдеры, шрифты, splash и навигацию. В `app/` нет доменных API, общих компонентов или stores. Системный store версии находится в `features/system/store/version.store.ts`.

## Запросы и состояние

| Код | Владелец |
| --- | --- |
| Вход, регистрация, OTP и операции аккаунта | `features/auth/api/auth.api.ts` |
| Категории услуг | `features/services/api/service-categories.api.ts` |
| Товары и магазины | `features/home/api/products.api.ts`, `shops.api.ts` |
| Заказы | `features/orders/api/orders.api.ts` |
| Отзывы | `features/profile/api/reviews.api.ts` |
| Общий HTTP-транспорт | `shared/api/api.ts`, `query-client.ts` |
| Supabase-клиент и вспомогательные функции | `shared/api/supabase/` |
| Хранение токенов | `shared/lib/storage/token-storage.ts` |

Общий `apiSlice.ts` разделён по владельцам. Поведение запросов, endpoints, query keys и invalidation сохранено.

Демонстрационные заказы централизованы в `shared/mocks/mock-data.ts`: список и детали используют `fetchMockData("orders")`. Экран списка не дописывает собственные записи. Уникальность ID и повторная загрузка проверяются командой `node tests/orders.test.cjs`.

По запросу пользователя вкладка «Заказы» временно сначала показывает `features/services/components/category-image-gallery.tsx`: 20 иллюстраций Thiings с названиями предложенных категорий, без раздела похоронной помощи. Кнопка «К заказам» возвращает список, а «Изображения категорий» повторно открывает подборку. Переключатель представления принадлежит экрану заказов; галерея получает только `onClose`, без доступа к заказам или чужим stores. Старый компонент выбора Ionicons сохранён, но не подключён.

Иллюстрации и сведения об источниках находятся в `assets/imgs/catalog/`. Главная, поиск и выдача используют согласованные 19 разделов и 169 подкатегорий из `sources.json` через `features/services/api/catalog.data.ts`; основные PNG подключены статически в `features/services/utils/catalog-images.ts`. На главной `FlatList` показывает максимум пять плиток раздела; заголовок открывает полный список в существующей `CategorySheet`. Подписи аудитории различают мужской и женский уход. Прежние изображения проекта сопоставлены с подкатегориями в `legacy-mapping.json`, альтернативы сохранены в `sources.json`. Раздел «Транспорт и поездки» исключён по запросу пользователя. Отдельная галерея изображений категорий использует `category-illustrations.ts`, виртуализированную сетку и зарезервированную область PNG. Условия коммерческого использования Thiings указаны в README рядом с файлами; наличие платной лицензии не проверено.

Демонстрационная сессия экранов принадлежит `features/auth/store/use-auth-store.ts`; адреса и избранное — `features/profile/store/use-profile-store.ts`. Потребители используют эти stores напрямую; промежуточного `shared/stores` нет.

Главный экран профиля отображает текущего пользователя из auth-store и вызывает его `logout()` после подтверждения. Переключатель темы использует общий `theme-mode.store`, без отдельной копии настройки в профиле. Оформление и ограничения описаны в [profile-screen.md](profile-screen.md).

Демонстрационный каталог принадлежит `features/services/api/catalog.data.ts`, контракты — `features/services/types/catalog.types.ts`, фильтрация — `features/services/utils/filter-catalog.ts`. Главная и поиск используют этот единый каталог. Избранное хранит идентификаторы предложений в существующем profile-store в пределах сессии; сетевой синхронизации пока нет.

`features/auth/store/server-auth.store.ts` сохраняет отдельный прежний серверный контракт с токенами и OTP. Подключение его вместо демонстрационной сессии требует отдельной интеграции; структурный перенос не изменяет механизм входа.

Общие modal/toast stores находятся в `shared/store/`. Имена `swipeable-modal.store.ts` и `swipeable-toast.store.ts` отличают прежние контракты жестовых компонентов от `modal.store.ts` и `toast.store.ts`, импортированных из `ch.auto`.

Фичи взаимодействуют через явные параметры и доменные контракты. `shared` не импортирует код `features` или `app`. Не создавай повторный store для уже существующего состояния.

## Тема и текущие ограничения

Вся тема собрана в `shared/theme/`: `index.ts`, `light.ts`, `dark.ts`, `tokens.ts`, `types.ts`, существующие `palette.ts` и `design-system.ts`. Это единое расположение файлов; полной унификации визуальных токенов и API двух наборов компонентов ещё не было.

Упоминание ALLIN внутри подписи отображается через `shared/components/allin-text`: компактный знак наследует цвет и размер шрифта, учитывает системный масштаб. Для отдельных логотипов используется существующий `AllinLogo`. Исходный текст сохраняется в данных, поиске и accessibility-label.

Главная и профиль завершаются общим `AppFooter`: логотип `AllinLogo` шириной 44 pt, окрашенный по теме, без подписи версии. В профиле компонент компактный, без собственной минимальной высоты и padding. Только главная передаёт блок минимальной высотой 64 pt и нижний padding 16 pt через style: логотип центрирован внутри него после всех категорий; нижнюю safe area учитывает навбар.

Существующие mocks, заглушки и ошибки зависимостей сохранены и перечислены в [проверке унификации](folder-normalization.md). Правила работы — в [AGENTS.md](../AGENTS.md), каталог навыков — в [skills.md](skills.md).
