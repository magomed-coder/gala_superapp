# Унификация папок

Дата: 4 ноября 2026 года. Текущая структура описана в [architecture.md](architecture.md).

## Изменения

- Прикладной код собран в трёх разделах: `app`, `features`, `shared`.
- Корневые `components`, `core`, `contexts`, `constants`, `hooks`, `lib`, `mocks`, `services` разобраны по ответственности и удалены после переноса файлов.
- У всех восьми фич одинаковые разделы: `api`, `components`, `hooks`, `screens`, `store`, `types`, `utils`.
- Имена файлов и папок прикладного кода приведены к `kebab-case`, кроме специальных имён Expo Router. Имена экспортируемых компонентов сохранены.
- 62 общих компонента оформлены как `shared/components/<component-name>/index.tsx`. iOS-реализация `icon-symbol` находится рядом с базовой.
- Общие barrel-файлы `ui`, `atoms`, `molecules`, `modals` и совместимые `shared/stores`, `services` удалены; потребители используют прямые импорты.
- Одноимённые компоненты с разными API получили разные пути: например, `button` и `themed-button`. Их реализации не объединялись автоматически.
- Общий файл query hooks разделён на доменные API услуг, магазинов, товаров, заказов и отзывов. Контракты запросов сохранены.
- Общие stores, hooks, тема и инфраструктура размещены в соответствующих разделах `shared`. Серверный auth store относится к `features/auth`, store версии приложения — к `features/system`.
- Обновлены `AGENTS.md`, проектный `feature-boundaries`, README, Quickstart и документация архитектуры.

## Проверки

| Проверка | Результат |
| --- | --- |
| Маршруты | Те же 35 файлов маршрутов и layout |
| Структура фич | Все 8 имеют одинаковый набор каталогов |
| Общие компоненты | 62 папки с `index.tsx`; платформенный вариант сохранён |
| Локальные импорты | Проверена 281 связь, новых отсутствующих модулей нет |
| Границы слоёв | `shared` не импортирует `features` или `app` |
| `npm run typecheck` | 125 существующих ошибок до и после; новых диагностик нет |
| `npm run lint` | 57 существующих ошибок и 24 предупреждения до и после; новых диагностик нет |

Диагностики сравнивались с учётом новых путей и сдвига строк после разбиения импортов. Старые ошибки не скрывались через исключения TypeScript или отключение правил ESLint. `npm run lint` проверяет все три раздела приложения.

## Оставшиеся ограничения

Перенос структуры не завершает интеграцию кода из `ch.auto`. Уже до этой работы отсутствовали изображения `assets/imgs/*`, типы Supabase, `safeStateStorage` и некоторые зависимости. Теперь ожидаемые пути для типов БД и storage-адаптера — `shared/api/supabase/database.types.ts` и `shared/lib/storage/safe-state-storage.ts`.

Сохраняются прежние ошибки props `Text`, типов темы и анимаций, hooks и заглушки версии приложения. Визуальные токены и разные API компонентов пока не объединены; оба контракта находятся в общей структуре с различимыми именами.

Проверка на устройстве или симуляторе не выполнялась. Полный список проблем первого переноса приведён в [историческом отчёте](migration-validation.md).
