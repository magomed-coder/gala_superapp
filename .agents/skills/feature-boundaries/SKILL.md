# Границы фич ALLIN

Перед изменением прочитай docs/architecture.md из корня проекта.

## Владельцы и зависимости

- Маршруты и навигаторы находятся в app/. Экраны, доменные API, hooks, store, types и utils — в features/<domain>/.
- Для каждого состояния определи владельца и время жизни. Поисковый запрос принадлежит search, заказ — orders, профиль — profile, сессия — auth. Не объединяй независимые stores через spread в универсальную сессию.
- Передавай явные параметры: userId, orderId, serviceId и критерии поиска. Доменные API не читают чужой UI-store. Композиция сценария может обращаться к публичным API нескольких фич.
- Общий HTTP-клиент и QueryClient находятся в shared/api/, хранение токенов — в shared/lib/storage/. Переиспользуемый UI — в shared/components/, инфраструктура — в shared/lib/, темы — в shared/theme/, общие stores — в shared/store/. Shared не должен зависеть от features или app.
- Новые доменные запросы размещай в features/<domain>/api/. Общие query hooks нескольких областей и технические services-каталоги не используются. Запросы товаров и магазинов принадлежат home, категорий услуг — services, заказов — orders, отзывов — profile.
- У состояния должен быть один источник истины. Потребители напрямую используют features/auth/store/use-auth-store.ts и features/profile/store/use-profile-store.ts. features/auth/store/server-auth.store.ts — отдельный прежний серверный контракт; не подключай его параллельно к тому же сценарию без согласования модели сессии.

## Единая структура

- Файлы и папки называются в kebab-case. Специальные имена маршрутов Expo Router сохраняются.
- У фич одинаковые разделы: api, components, hooks, screens, store, types, utils. Не вводи синонимы helpers/stores/services.
- Общий компонент находится в shared/components/<component-name>/index.tsx. Импортируй из его папки; не создавай общий barrel UI.
- Сохраняй различимые контракты компонентов: button и themed-button не взаимозаменяемы только из-за похожего названия.

## Запросы и интерфейс

- Ошибка или занятость одной фичи не блокирует другую. Фоновое обновление сохраняет загруженное содержимое.
- Ключи Query учитывают пользователя и параметры ответа; поздний ответ не подменяет результат другого поиска или аккаунта.
- Сохраняй исходное намерение записи при неопределённом результате. Проверяй результат перед повтором, если операция может продублироваться.
- Не вводи абстракции ради количества папок. Общие типы и компоненты выноси при реальном переиспользовании.
- Добавляй содержательные русские комментарии к новым функциям и смысловым JSX-блокам; сохраняй форматирование и требования AGENTS.md к доступности.

## Проверка

Обнови документацию по фактической реализации. Проверь потребителей, первую загрузку, ошибку/повтор и смену параметров затронутого сценария. Запусти npm run lint и npm run typecheck; отделяй существующие ошибки от новых. Не подменяй проверку поведения поиском строк в исходниках.
